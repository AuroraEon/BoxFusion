# RSLG-SLAM Workspace Contract

This workspace contract documents intended repository organization without reorganizing the repository.

## Source Areas

Source code and lightweight tracked project files should live under:

- `boxfusion/`
- `tools/`
- `config/`
- `tests/`
- `docs/rslg_slam/`

Future canonical tools should converge under `tools/rslg_pipeline/` through explicit migration tasks. Existing tools must not be moved or deleted by ordinary planning tasks.

## Generated Evidence

`stage_outputs/` is a generated-output workspace, not permanent project truth.
It may be backed up, deleted, or regenerated by explicit user decision. Static
RSLG-SLAM validators must not require historical `stage_outputs/` paths to
exist.

Generated task evidence should live under:

`stage_outputs/.../tasks/<task_id>_<task_name>/`

Large rerun candidates should live under:

`<scene_root>/<task_id>_*_candidate/`

`clean_rerun` is canonical promoted output. Ordinary tasks must not write into it.

Historical generated evidence, including the 00824 reference baseline when it is
present in the workspace, is read-only for ordinary tasks and must not be
modified, moved, renamed, or deleted by those tasks. Its absence after an
explicit user backup/deletion decision is not a static-validation failure.

Runtime evidence must not be promoted into `committed_public`.

## Git Policy

Track source code, configuration, tests, RSLG-SLAM documentation, and lightweight manifest/specification files. Ignore generated stage outputs, runtime directories, logs, scratch files, large raw outputs, point clouds, images, videos, ROS bags, PGM maps, temporary arrays, and runtime logs.

This task records proposed git policy in manifests only and does not modify `.gitignore`.
