# Model Usage Audit Report

## Executive summary

The current paper-safe Stage-A backend is driven by `stage_a_demo.py:458-585`, not by the older `demo.py` CLI. The Stage-A wrapper loads three runtime model assets before handing control to `demo.run`: a BoxFusion / Cubify RGB-D checkpoint from `--model-path`, a CLIP checkpoint resolved from `models/`, and a precomputed text-feature tensor resolved from `data/`.

In the current workspace, the active vision-language stack is the smaller `ViT-B-32` CLIP variant. The evidence is:

- `stage_a_demo.py:473-475` defaults to `--clip-model-name ViT-B-32` and optional `--clip-path` / `--text-features`.
- `stage_a_demo.py:47-68` prefers `./models/ViT-B-32/open_clip_pytorch_model.bin` and `./data/class_features_small.pt` before falling back to the older root-level assets.
- `models/ViT-B-32/open_clip_config.json` declares `embed_dim: 512`, `vision_cfg.width: 768`, and `patch_size: 32`.
- Archive metadata shows `data/class_features_small.pt` stores a `473 x 512` tensor, while `data/class_features.pt` stores a `473 x 1024` tensor.

The main Stage-A path does not load a learned room-segmentation checkpoint. Floor-aware room segmentation is performed by `FloorAwareRoomSegmenter` / `DynamicRoomSegmenter` over accumulated RGB-D point clouds and fused objects (`demo.py:714-720`, `demo.py:1042-1111`, `boxfusion/floor_aware_room_segmenter.py:247-316`). The SegFormer assets under `models/segformer-b0-finetuned-ade-512-512/` are present but are not clearly referenced by the runnable Stage-A backend.

Downstream artifact-backed query and room-graph routing do not reload model checkpoints. They consume exported JSON artifacts:

- `stage_a_topology_query.py` loads `logs/topology_v0_1.json` through `RoomTopologyQueryAPI.from_json(...)`.
- `stage_a_room_graph_vln_demo.py` loads `logs/topology_v0_1.json` and `logs/committed_room_world_model_v0_1.json`.
- `stage_a_eval/run_backend_eval.py` evaluates exported topology artifacts through `RoomTopologyQueryAPI.from_json(...)`.

## Main runnable model stack

### 1. Stage-A entrypoint and checkpoint load

- `stage_a_demo.py:466-545` is the main paper-safe CLI entrypoint.
- `stage_a_demo.py:537-545` loads `args.model_path`, extracts `checkpoint["backbone.0.patch_embed.proj.weight"]`, builds the model with `make_cubify_transformer(..., depth_model=True)`, and loads the state dict.
- Archive metadata for `models/cutr_rgbd.pth` shows `backbone.0.patch_embed.proj.weight` has shape `768 x 3 x 16 x 16`, so the current detector backbone width is `768`.

### 2. CLIP load

- `stage_a_demo.py:547-553` loads CLIP with `open_clip.create_model_and_transforms(model_name=args.clip_model_name, pretrained=clip_path)`.
- `stage_a_demo.py:47-56` resolves the CLIP checkpoint in this order:
  1. CLI `--clip-path`
  2. `./models/ViT-B-32/open_clip_pytorch_model.bin`
  3. `./models/open_clip_pytorch_model.bin`

### 3. Text classes and text features

- `stage_a_demo.py:555-565` loads the class list from `args.class_txt` and the text-feature tensor from the resolved text-feature path.
- `stage_a_demo.py:59-68` resolves text features in this order:
  1. CLI `--text-features`
  2. `./data/class_features_small.pt`
  3. `./data/class_features.pt`
- `stage_a_demo.py:88-134` checks feature dimensionality against the active CLIP model and auto-rebuilds text features when there is a mismatch.
- `data/panoptic_categories_nomerge.txt` has `473` labels (`wc -l`), so both text-feature tensors are aligned to a 473-class vocabulary.

### 4. Runtime handoff into the backend loop

- `stage_a_demo.py:576-585` passes the loaded detector, CLIP model, preprocessing transform, class labels, text features, augmentor, and preprocessor into `_run_single_sequence(...)`.
- `_run_single_sequence(...)` calls `demo.run(...)` with those assets plus the selected dataset (`stage_a_demo.py:167-239`).

### 5. Real-backend ROS wrapper

The ROS simulation ingress path is consistent with the same Stage-A stack:

- `boxfusion/ros_simulation_ingress.py:70-72` defaults to:
  - `./models/cutr_rgbd.pth`
  - `./models/ViT-B-32/open_clip_pytorch_model.bin`
  - `./data/class_features_small.pt`
- `boxfusion/ros_simulation_ingress.py:1015-1028` hardcodes `--clip-model-name ViT-B-32` when it shells out to `stage_a_demo.py`.
- `boxfusion_ros_query_server/launch/simulation_ingress.launch.py:114-126` exposes matching launch defaults.

## CLIP / text-feature setup

### Active setup

- Backbone name: `ViT-B-32`
  - Configured by default in `stage_a_demo.py:474`.
  - Also hardcoded in `boxfusion/ros_simulation_ingress.py:1023-1028`.
- Preferred checkpoint: `models/ViT-B-32/open_clip_pytorch_model.bin`
  - Preferred by `stage_a_demo.py:47-56`.
- Paired text-feature file: `data/class_features_small.pt`
  - Preferred by `stage_a_demo.py:59-68`.
  - Generated by the helper script `gen_features.py:7-44`.
- Class vocabulary: `data/panoptic_categories_nomerge.txt`
  - Loaded by `stage_a_demo.py:555`.

### Why this appears to be the smaller ViT variant

- `models/ViT-B-32/open_clip_config.json` declares:
  - `embed_dim: 512`
  - `vision_cfg.layers: 12`
  - `vision_cfg.width: 768`
  - `vision_cfg.patch_size: 32`
- `data/class_features_small.pt` archive metadata is `473 x 512`, matching a 512-dim CLIP text/image embedding space.

### Larger CLIP assets that still exist

- `models/open_clip_pytorch_model.bin` is still present and still referenced, but only as a fallback in the Stage-A wrapper and as the default in the older `demo.py` CLI.
- `README.md:49-54` documents the root-level file as the downloaded CLIP checkpoint from the `CLIP-ViT-H-14-laion2B-s32B-b79K` page.
- Archive metadata from `models/open_clip_pytorch_model.bin` shows:
  - `visual.conv1.weight`: `1280 x 3 x 14 x 14`
  - `visual.proj`: `1280 x 1024`
  - `text_projection`: `1024 x 1024`

That strongly suggests the root-level file is a larger `ViT-H-14`-style checkpoint. This is an inference from asset metadata plus `README.md`, not from an explicit runtime config key.

### How text-feature rebuilding behaves

- `stage_a_demo.py:114-134` compares CLIP embedding dimension and text-feature dimension.
- If they mismatch, it rebuilds text features with `open_clip.get_tokenizer(clip_model_name)` and `clip_model.encode_text(...)`.
- The auto-generated save path is:
  - `./data/class_features_small.pt` for `ViT-B-32`
  - `./data/class_features_<safe_model_name>.pt` for other backbones (`stage_a_demo.py:79-85`)

For a controlled paper comparison, relying on this rebuild path is functional, but pinning an explicit new text-feature file is cleaner.

## Detection / segmentation / fusion model usage

### Detection

- `demo.py:1020-1031` runs `pred_instances = model(packaged)[0]` on keyframes and applies score, UV-bound, and floor-mask filtering.
- The detector is the only learned 3D detection checkpoint on the main path.

### Semantic classification

- `demo.py:1344-1352` classifies all boxes on the first keyframe with `text_prompt(...)`.
- `demo.py:1685-1694` classifies only newly retained boxes after association / fusion on later keyframes.
- `tools/utils.py:441-460` crops each 2D box, encodes crops with CLIP, scores against the precomputed text-feature matrix, and assigns the best class label.
- `demo.py:1323-1325` initializes `pred_instances.categories` and `pred_instances.embeddings`; later steps store CLIP image features back into the instance store (`demo.py:1691-1694`).

### Object fusion / semantic association

- `demo.py:1477-1517` performs 3D OBB NMS via `Instances3D.spatial_association(...)`.
- `demo.py:1521-1574` performs small-object correspondence association.
- `demo.py:1576-1671` performs multi-view `BoxFusion` when `cfg["box_fusion"]["use"]` is true.
- `demo.py:1405-1435` and `demo.py:1582-1594` constrain association / fusion candidates with floor-aware history masks derived from `FloorAwareRoomSegmenter`.
- `boxfusion/box_fusion.py:31-64` loads the PST lookup table from `cfg["box_fusion"]["pst_path"]`, so `data/pst_1024_0.tiff` is a direct runtime asset.

### Floor-aware room segmentation

- `demo.py:720` constructs `FloorAwareRoomSegmenter`.
- `demo.py:1042-1073` backprojects RGB-D into world-space point clouds and feeds downsampled chunks into `room_segmenter.observe_frame(...)`.
- `demo.py:1097-1111` triggers `room_segmenter.perform_segmentation(...)` every `room_seg_interval` frames.
- `boxfusion/floor_aware_room_segmenter.py:247-316` shows that segmentation is scheduled from pose observations and accumulated point chunks, not from a learned checkpoint.
- `boxfusion/floor_aware_room_segmenter.py:468-760` exports rooms, vertical transitions, objects, anchors, and relationships into the final vector-map structure.

### Learned segmentation assets that are not on the main path

- `boxfusion/segmentor.py:7-48` defines `SceneSegmenter`, which loads `./models/segformer-b0-finetuned-ade-512-512`.
- A repo-wide search only finds that definition; there are no imports or call sites elsewhere.
- Therefore the SegFormer checkpoint set is present but not clearly referenced by the runnable Stage-A backend.

## What would be required for a controlled larger-backbone test

### Direct `stage_a_demo.py` path

To run a controlled larger-backbone comparison without changing the architecture:

1. Keep the detector checkpoint, dataset, config, and Stage-A flags fixed.
   - Keep `--model-path`, `--config`, `--seq` / `--seqs`, `--room-seg-interval`, `--box-fusion-mode`, and `--history-scope-mode` constant.
2. Pass a matching larger CLIP checkpoint and backbone name.
   - Example knobs are already exposed in `stage_a_demo.py:472-475`.
   - Required changes are `--clip-model-name <larger_model>` and `--clip-path <matching_checkpoint>`.
3. Use a matching text-feature tensor.
   - Best practice: precompute and pin a new file such as `data/class_features_<larger_model>.pt`.
   - The wrapper can auto-rebuild on mismatch (`stage_a_demo.py:88-134`), but an explicitly pinned file is cleaner for a paper comparison.
4. Keep the class vocabulary file fixed.
   - Continue using `data/panoptic_categories_nomerge.txt` unless the comparison intentionally changes label space.

### `run_paper_ablation_harness.py` path

- `stage_a_eval/run_paper_ablation_harness.py:45-90` forwards `--clip-path`, `--text-features`, and `--class-txt` to `stage_a_demo.py`.
- It does **not** expose a dedicated `--clip-model-name` flag (`stage_a_eval/run_paper_ablation_harness.py:153-190`).
- For a controlled larger-backbone test through this harness, you would need either:
  - `--extra-arg --clip-model-name --extra-arg <larger_model_name>`, or
  - a small harness patch to add a first-class `--clip-model-name` argument.

### ROS real-backend path

- `boxfusion/ros_simulation_ingress.py:1015-1028` hardcodes `--clip-model-name ViT-B-32`.
- `boxfusion/ros_simulation_ingress.py:70-72` and `boxfusion_ros_query_server/launch/simulation_ingress.launch.py:114-126` also default to the smaller-stack asset paths.
- A controlled larger-backbone ROS comparison would therefore need:
  - a new larger `real_backend_clip_path`
  - a matching `real_backend_text_features`
  - a way to pass the larger `clip-model-name` instead of the current hardcoded `ViT-B-32`

### Feature-generation helper

- `gen_features.py:7-44` is currently hardcoded to `ViT-B-32`, `data/class_features_small.pt`, and an absolute local checkpoint path.
- If this helper is used for the larger-backbone comparison, it would need corresponding parameter changes or light parameterization.
